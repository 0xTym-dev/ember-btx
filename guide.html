Setup Guide

From zero to mining, step by step.

No prior mining experience needed. This walks you through everything — installing AMD's runtime, getting an address, and starting Ember — in plain language. Budget about 15 minutes, most of it waiting on downloads.

What you need

Three things. If you have all three, you're ready.

An AMD Radeon GPU

Any RDNA2, RDNA3 or RDNA4 card — RX 6000, RX 7000 or RX 9000 series. See the supported list.

Linux or Windows

Native Linux, or Windows 10/11 through WSL2. Windows needs an RX 7000/9000 card (RDNA2 is Linux-only).

A BTX address

Where your rewards land. It starts with btx1. Step 2 shows how to get one safely.

1

Install ROCm

ROCm is AMD's GPU compute runtime — the equivalent of NVIDIA's CUDA. Ember needs it to talk to your card. You install it once.

On native Linux

Install your distribution's ROCm runtime package (version 6.x or newer), then confirm the card is visible:

Ubuntu / DebianArch / CachyOSFedora

Ubuntu / Debian

# follow AMD's amdgpu-install for your release, then: sudo apt install rocminfo rocm-smi-lib

Arch / CachyOS

sudo pacman -S rocminfo rocm-smi-lib

Fedora

sudo dnf install rocminfo rocm-smi

Then check your GPU shows up — you're looking for a gfx.... name:

rocminfo | grep -m1 gfx # e.g. gfx1101

On Windows (WSL2)

No native Windows build is needed — you run the Linux binary inside WSL2, which AMD officially supports for RX 7000 and RX 9000 cards.

# 1. install the AMD Adrenalin "WSL2" driver on Windows first, then in PowerShell: wsl --install Ubuntu-24.04 # 2. inside Ubuntu, install ROCm for WSL: amdgpu-install --usecase=wsl,rocm --no-dkms rocminfo | grep -m1 gfx

If rocminfo prints your card, you're done here. That single line is the whole test — everything else in Ember depends on it working.

2

Get a BTX address

Your rewards are paid to a BTX address you control. Ember never creates or holds a wallet — you just hand it a receiving address.

You get one from a BTX wallet: run a BTX full node and call getnewaddress, or use any BTX wallet that gives you a receive address beginning with btx1.

Only ever give Ember your public receive address. Never type or paste a seed phrase or private key anywhere — not into Ember, not into any website. Ember only needs the btx1… address to tell the pool where to credit your shares.

Back up your wallet, and if you're mining somewhere new, double-check the address is really yours before you point a rig at it.

Learn more about the coin itself on the What's BTX? page.

3

Download & verify

Grab the latest release, unpack it, and let Ember's installer check everything before you mine.

Download ember-<version>-linux-x86_64.tar.gz from the releases page, then:

tar xzf ember-*-linux-x86_64.tar.gz cd ember-* ./install.sh

install.sh is a preflight, not a system installer — it doesn't touch anything outside the folder. It checks that:

ROCm is present, your GPU architecture is one Ember ships code for, Python is available, and the solver binary matches its published SHA-256 checksum — so you know the download wasn't tampered with.

4

Start mining

One command. Swap in your address and pick any worker name.

./ember --address btx1z…your-address --worker rig1

That's it. Ember connects to the public minebtx pool, authorizes your worker, loads the solver, and starts submitting shares. You'll see lines like ✓ share accepted as they land.

The first share can take a few minutes. Pools start you at an entry difficulty and calibrate to your card over time — a quiet first stretch is normal, not a bug. The --worker name is just a label so you can tell rigs apart on the pool dashboard.

Pointing at a different pool

Ember uses stratum.minebtx.com:3333 by default. To use another pool, add --pool host:port.

./ember --address btx1z… --worker rig1 --pool stratum.example.com:3333
5

Watch the dashboard

Add one flag and Ember opens a live dashboard in your browser.

./ember --address btx1z… --worker rig1 --gui

It serves a read-only page at 127.0.0.1:8787 showing live hashrate, accepted/rejected shares, GPU temperatures, power, clocks and a live log. Nothing leaves your machine — it reads straight from the running miner and rocm-smi. Change the port with --gui-port, or skip auto-opening the browser with --no-open.

6

Tune your card

Every GPU has a sweet spot. Ember can find yours automatically.

./ember --address btx1z… --worker rig1 --deep-tune

DEEP TUNE runs the miner with different batch sizes and CPU-feed settings, measures the real scan rate for each, and saves the best combination for your exact card to ~/.ember/. Every later run loads it automatically — no flags needed.

It takes a while — that's the point, so run it once, ideally while you're away. Add --tune-objective efficiency to optimize for nonces-per-watt instead of raw speed.

7

Run efficiently

The solver is memory-bound, so you can cut power a lot without losing hashrate.

Because the bottleneck is memory bandwidth, capping the core clock at roughly 1900 MHz holds essentially the same scan rate while dropping power by about a third. On native Linux you set this through your GPU's performance controls; on Windows, set the clock and power limits in AMD Adrenalin on the Windows side (they aren't reachable from inside WSL2).

Efficiency tuning of clocks and power lives outside Ember on purpose — it needs system-level access and is card-specific. Ember focuses on the safe runtime knobs (batch size, feed workers) that don't require root.

8

Troubleshooting

The handful of things that trip people up, and the fix for each.

rocminfo shows nothing / no gfx line

ROCm can't see the GPU. On Linux, make sure your user is in the render and video groups and reboot. On WSL2, confirm you installed the Adrenalin WSL2 driver on Windows and used --usecase=wsl,rocm inside Ubuntu.

"unsupported gfx" from install.sh

Your architecture isn't in the shipped build. Ember covers RDNA2/3/4 gaming cards; if rocminfo reports something outside that set, open an issue — adding an arch is just a rebuild.

No shares for the first few minutes

Expected. The pool starts at an entry difficulty and calibrates to your card. Give it time; the --gui dashboard shows the live scan rate so you can confirm the GPU is actually working while you wait.

It says something about a developer fee

That's Ember being honest. A flat 1% of mining time goes to the developer address, disclosed at startup and every fee round. The other 99% is yours. Full detail on the landing page.

Still stuck? Open an issue on GitHub with your rocminfo output and the first 20 lines Ember prints — that's almost always enough to pinpoint it.
